## 2. Pekerjaan implementasi

1. Inventarisasi layar dan state terhadap route Compose serta API aktual. Dokumentasikan pemetaan mockup → layar/komponen → sumber data → bukti sebelum mengerjakan. Gunakan subagent paralel bila tersedia: sistem visual/komponen; layar/alur; widget/notifikasi. Tetapkan satu penanggung jawab setiap file bersama. Gunakan kembali subagent relevan dan tutup yang selesai. Pemilik menentukan model/effort. Lakukan audit independen setelah integrasi.
2. Terapkan desain di Masuk/Daftar, Gmail Tautkan/Lewati, Ringkasan, Transaksi, Detail dan Tambah Transaksi, Analisis, Pengaturan, serta Kelola Kategori. Gunakan satu route daftar Transaksi untuk tab dan drill-down Ringkasan. Pertahankan filter, pagination, back dan cara masuk kembali ke Ringkasan. Pertahankan catatan, koreksi kategori USER, validasi masa depan/WIB, state offline/gagal dan izin Gmail/AI terpisah. Hilangkan duplikasi banner Livin, kartu Sumber data dan ikon Pengaturan di top bar bila masih ada.
3. Gunakan judul terpusat dan ikon status sinkronisasi dengan label sementara. Gunakan satu bottom sheet yang memuat aksi mulai/retry, progres dan ringkasan hasil. Menutup sheet tidak membatalkan proses. Membuka kembali memulihkan status aktual. Pertahankan daftar saat refresh dan jangan mengarang persentase. Hindari layar Impor kedua.
4. Terapkan opsi B untuk kartu bank. Satu kartu per bank, jumlah transaksi tercatat sesuai periode, Mandiri pertama. Tampilkan kartu penuh ketika hanya satu bank; saat ada beberapa bank yang benar-benar didukung, gunakan carousel dengan snapping, indikator posisi dan alternatif navigasi aksesibel. Jago/BRI hanya untuk preview sintetis. Gunakan data berdimensi bank yang benar; jangan menganggap seluruh transaksi manual atau total akun sebagai Mandiri. Jika kontrak bank belum tersedia, siapkan komponen/preview dan laporkan gap sumber data. Jangan mengarang klasifikasi bank atau filter transaksi berdasarkan swipe. Cakupan baru yang memerlukan perubahan produk diputuskan pemilik.
5. Siapkan widget Jetpack Glance 2×2 dan 4×2 sesuai CR-010. Satu bank per widget, nama bank, bulan WIB dan jumlah transaksi yang benar. Tap membuka Ringkasan dengan bank/periode sesuai cakupan aktif. Tangani belum login, loading, kosong terkonfirmasi dan snapshot offline yang bertanggal. Bersihkan data launcher ketika logout/pindah akun/hapus akun. Gunakan snapshot agregat milik akun aktif, pembaruan hemat dan tanpa panggilan AI.
6. Implementasikan notifikasi transaksi baru di profil uji sesuai CR-010. Default nonaktif, izin Android dan pengaturan channel dihormati. Hanya transaksi Livin baru dari delta yang sudah tersimpan. Kelompokkan per siklus, dedupe retry/replay, kecualikan backfill dan manual. Tap satu membuka detail; kelompok membuka daftar terkait setelah validasi sesi/kepemilikan. Preview layar kunci tanpa nominal atau merchant. Gunakan event stabil dan jalur Go yang bisa dites tanpa FCM live. Jika konfigurasi FCM nyata tersedia dan sudah disetujui, uji di lingkungan terisolasi; bila belum, catat prasyarat. Jangan membuka billing, mengaktifkan fitur di produksi, atau meletakkan rahasia di repo.
7. Pertahankan scope produk. Anggaran, lampiran, kamera/OCR, admin dan perintah pembayaran tidak termasuk. Jangan ubah backend hanya untuk menyesuaikan tampilan. Jika kontrak widget/notifikasi perlu perubahan, kerjakan di repo Go terpisah dan uji kompatibilitas Android.

## 3. Bukti dan serah terima

- Uji Android lewat Run konfigurasi app debug di Android Studio dengan endpoint yang dipakai pemilik. Uji 360/393/412 dp, font 200%, TalkBack, area sentuh, IME dan contrast. Ambil screenshot layar runtime asli dan catat deviasi dari Stitch. Bedakan hasil emulator, HP fisik dan preview.
- Jalankan regresi Android yang relevan, build dan lint. Jika Go berubah, jalankan suite yang relevan, vet dan build. Uji flow Ringkasan → Transaksi → Ringkasan, koreksi kategori, tutup/buka sheet saat sync, rollover periode widget, logout/pindah akun, izin ditolak, notifikasi tunggal/kelompok, duplikat dan aplikasi ditutup normal. Bedakan fixture dari Gmail/FCM live.
- Buat commit kecil dan langsung push setiap commit ke branch kerjanya. Gabungkan branch subagent ke branch kerja yang sesuai setelah audit. Hapus branch sementara lokal/remote setelah integrasi terbukti dan tidak ada pekerjaan unik. Merge ke main dan deploy mengikuti izin pemilik yang berlaku. Pertahankan WIP pihak lain.
- Perbarui README dan PROGRESS_DAILY untuk tanggal WIB yang sama. Laporkan perubahan per layar dan fitur, bukti dan screenshot, commit serta status PASS/PARTIAL/FAIL/NOT RUN. Selesaikan semua bagian yang dapat diterima secara independen dan laporkan penghambat nyata beserta tindakan yang dibutuhkan.
