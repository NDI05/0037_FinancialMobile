## Batasan / hal yang tidak diklaim

- Log allow-list server hanya memuat method/route/status/correlationId/ms — **tanpa query string,
  payload, atau header**. Karena itu payload dibuktikan dari (a) baris hasil GET owner API,
  (b) request yang ditangkap relay pada skenario C; bukan dari URL log.
- Skenario C memakai relay host untuk menghilangkan respons; yang terbukti adalah perilaku retry
  app pada koneksi terputus (otomatis dalam detik yang sama, key sama) plus kontrak replay server.
  Tidak ada klaim bahwa setiap jalur jaringan lain (timeout lambat, proxy korporat) diuji.
- Kalibrasi harness sebelum bersih: log endpoint mencatat 2× `POST /v1/transactions` **400** pada
  `19:09:38/19:09:53` (draf lama tergabung — penyebab yang sama dengan PARTIAL sebelumnya) dan
  1× **201** pada `19:10:18` (`req_245a4fd9…`) dari tap kalibrasi yang tidak dipakai sebagai
  bukti. Baris kalibrasi itu tidak dapat diidentifikasi dari log route-only dan **tidak** dihitung
  sebagai bukti penerimaan; semua bukti penerimaan di atas memakai id baris yang terverifikasi.
- Akun sintetis disposable; persentase "vs bulan lalu" di Ringkasan tidak bermakna untuk data uji.
- Tidak ada perubahan kode produk yang diperlukan untuk C01; lane ini hanya menambah dokumen
  evidence ini.
